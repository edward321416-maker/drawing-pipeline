## 3. 붙여 넣은 파이프라인 요구와 현실의 차이

| 요구 | 1층 마스터 | 전체 건물 glb |

## 6. STEP 1 이후 적용할 슬라이싱 규칙(제안)

1. 입력이 `.glb`면 헤드리스 Blender로 가져와 접두어 → `kind`·`name_ko` 태그를 붙이는 어댑터를 거쳐 `.blend`로 저장한다. 사전에 없는 접두어는 빌드 거부(§6.2).
2. 층 높이는 `A-FLOR_s7_*` 윗면 z에서 읽는다. 절단 z = 층 높이 + 절단 높이(매개변수).
3. 절단 대상은 `column`·`*_wall`·`tube_wall`. 문·위생도기는 메시를 자르지 않고 변환 정보(중심, 회전, 폭, 깊이)만 뽑는다. 이 부분은 기존 `door`·`sanitary` 태그 구조와 맞는다.
4. 카메라·SVG viewBox·DXF 범위·PDF는 건물 외곽 + 15% 여백의 한 개 경계(`camera_bounds.json`)에 고정한다. 대지 도면(1:400)은 별도 경계를 쓴다.
5. 좌표계: 마스터는 로컬 (u,v), glb는 월드. 어댑터에서 `to_world` 역변환 또는 월드 기준 통일을 먼저 정해야 한다(아래 결정 사항).

## 7. 결정이 필요한 것 (사용자 몫)

1. **어떤 모델로 도면을 만들지** — (a) 벽·문이 있는 1층 마스터만, (b) 전체 건물 glb로 층별 구조·볼륨 도면, (c) 둘 다. 전체 건물에서 벽체 평면까지 원하면 벽·문·방 경계를 새로 모델링해야 한다.
2. **절단 높이** — 1.2 m(이번 요청) 대 1.5 m(승인된 설계 규칙).
3. **Gemini 인필** — API 키가 없고, 도면 이미지를 외부 서비스로 보내는 일이다. 키를 주고 허용하실지, 지금은 `--skip-ai`로만 갈지.
4. **패키지 설치** — `svgwrite`, `cairosvg`(Windows 의존성 문제 가능), `google-genai`를 설치해도 되는지. cairosvg가 안 되면 SVG → PDF/PNG 합성은 다른 라이브러리로 대체한다.
