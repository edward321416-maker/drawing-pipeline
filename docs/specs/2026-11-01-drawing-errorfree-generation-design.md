## 1. 목적

"그린 뒤에 눈으로 오류를 찾는" 현재 방식을 "**오류가 구조적으로 생기지 못하게 만들고, 생성 직후 기계가 검사하고, 통과한 것만 사용자에게 보이는**" 방식으로 바꾼다.

"무오류"의 정의: **미리 정의한 검사 항목에서 위반 0건**이다. 정의하지 못한 새로운 유형의 오류는 처음 한 번 나올 수 있다. 그 경우 결함 장부에 등록하고 검사를 추가하므로 같은 유형은 다시 나오지 않는다(§7).

## 3. 설계 원칙

- **P1 단일 진실 원천 (Single Source of Truth) = 태그된 Blender 3D 모델.** 1F의 모든 치수·위치·용도는 **마스터 3D 모델 한 벌**에만 존재한다. 단선도, 상세도, DXF, 검사기는 모두 이 모델을 절단·추출해서 얻는다. 그림 코드에는 숫자 좌표를 쓰지 않는다. 평면도는 "그린 것"이 아니라 "모델을 자른 것"이다.
- **P2 구성 시 검증 (Correct by Construction).** 배치를 손 좌표로 정하지 않고 규칙으로 계산한다.
  - 라벨은 영역 내부의 최적 지점(polylabel)에 놓고, 글자 크기가 들어가는지 확인해서 안 들어가면 지시선으로 밖에 낸다.
  - 가구는 영역에서 장애물과 이격 거리를 뺀 빈 공간 안에서만 배치한다.
  - 문 스윙은 벽·가구와 겹치지 않는 방향만 선택한다.
  - 면적 숫자는 폴리곤에서 계산해서 쓴다(타이핑 금지).
- **P3 파라메트릭 심볼 + 단독 검증.** 코어(피난계단+전실), 튜브 T1~T4, 화장실, 에스컬레이터 보이드를 각각 독립 심볼로 만든다. 각 심볼은 자기 점유 영역(keep-out), 라벨 자리, 필요 이격을 함께 선언한다. 심볼은 도면에 조립하기 전에 단독 시트에서 먼저 검사한다.
- **P4 검사는 산출물을 본다.** 모델 수준(shapely 기하)과 렌더 수준(실제 그려진 텍스트의 경계 상자, 사용된 선 두께)을 모두 검사한다. 검사기는 그림 코드와 별개이고, 자기 목록을 따로 갖지 않는다.
- **P5 실패하면 사용자에게 보이지 않는다.** 검사 위반이 1건이라도 있으면 산출물은 `_rejected` 폴더로 가고, 위반 목록(항목·좌표)만 남는다. `01_과정`에는 통과본만 들어간다.
- **P6 AI는 구조 권한이 없다.** 구조·치수·텍스트는 항상 벡터가 최종 상위 레이어다(§6).

### 5.3 Blender 모델 규약 (평면이 모델의 절단면이 되도록)

- **태그 의무.** 모든 객체는 사용자 정의 속성 `kind`(기둥, 외벽, 코어벽, 구획벽, 슬래브, 보이드, 튜브벽, 계단, 승강로, 기물, 구획존 등)와 `name_ko`(실명)를 가진다. 태그가 없거나 사전에 없는 객체가 있으면 빌드가 거부된다. 손으로 모델링해도 의미가 빠지지 않게 하는 게이트다.
- **평면은 절단면이다.** 절단 높이는 바닥 위 1.5 m(`params.yaml`)다. 절단된 윤곽은 Cut 선종으로, 절단면 아래 투영(디딤판 등)은 Projection Light로, 절단면 위 요소(보이드 경계, 상부 개구)는 Detail 점선으로 그린다. 선종은 `kind`가 정한다.
- **음영 렌더는 평면도가 아니다.** 현재 `D:\Users\admin\Desktop\2학기 논문\도면\01_과정\01_기획_구획_베이스\1F_블렌더_직교평면도.png`는 그림자가 있는 음영 렌더라 선 두께 위계가 없다. 이런 렌더는 3D 검토용으로만 쓴다. 평면도에 쓰는 선은 모델을 자른 벡터 윤곽(shapely)이다. 중간발표의 D2 규칙(같은 메시를 자른 벡터 절단선)과 같은 방식이다.
- **2D 요소는 모델에서 파생한다.** 문 스윙, 치수선, UP 화살표, 실명 텍스트, 면적은 모델에 넣지 않고 태그와 지오메트리에서 계산해 배치 솔버가 놓는다.
- **3D 간섭은 여러 높이에서 확인한다.** 기둥이 보이드·튜브·램프를 지나가는지 바닥 위 0.3 m, 1.5 m, 천장 아래 0.3 m 등 복수 높이 절단 폴리곤의 교차로 검사한다. 평면 한 장으로는 보이지 않는 관통을 잡는다.
- **마스터는 .blend다.** 초기 뼈대(격자·기둥·코어·튜브)는 스크립트가 태그를 붙여 한 번 생성해 출발점을 만든다. 이후 수정은 Blender에서 한다(사용자 직접 또는 Blender MCP). 수정한 모델을 스크립트로 다시 덮어쓰지 않는다.

## 6. 단계별 적용 (AGENTS.md 3단계 파이프라인과 1:1)

| 단계 | 생성 방식 | 통과해야 하는 검사 | 사용자 승인 |
|---|---|---|---|
| 0. 3D 모델 확정 | 기존 .blend와 승인본 단선도·CAD의 불일치 목록을 만들어 정답을 사용자가 지정한 뒤, 태그 규약에 맞춰 마스터 모델을 만든다. 3D 렌더로 확인받는다 | 태그 검증, 복수 높이 3D 간섭(G1·G2), C1 해소 | **승인 1** (3D 모델) |
| 1. 단선 | 마스터 모델의 구획 존·구조체를 절단해 파생 | G, T, C | **승인 2** |
| 2. 상세 | 심볼을 단독 시트에서 먼저 승인한 뒤 조립 (코어 → 화장실 → 튜브 → 보이드 순) | G, T, R, C | **승인 3** (심볼 단위 + 전체) |
| 3. 감성 인필 | 기본은 **절차적 인필** (가구·인물·수목 심볼을 배치 솔버로 배치). Nano Banana는 마스크로 제한한 자유 영역의 질감 참고용 옵션 | 위 전부 + P(보호 마스크 픽셀 차이) | **승인 4** |

3단계의 AI 사용 규칙:

- AI가 만든 래스터는 **자유 영역(보호 마스크 밖)만** 사용한다.
- 벽·기둥·튜브·코어·텍스트·치수는 벡터 렌더를 **최상위로 다시 합성**한다. AI가 바꿨어도 결과에 남지 않는다.
- 합성 후 보호 마스크 내부 픽셀을 벡터 렌더와 비교해서 차이가 임계 이상이면 거부한다(검사 P1).
- 스크립트 안에 픽셀 좌표를 박는 방식은 금지한다.

## 10. 한계와 범위 밖

- 검사는 **정의된 항목만** 잡는다. 미학적 균형(밀도, 리듬)과 취향은 기계가 판정하지 못하므로 사용자 승인 게이트에서 본다. 제시 전에는 자동 3×3 확대 크롭을 내가 직접 눈으로 확인한다.
- 기존 `scratch` 스크립트 수십 개는 정리하지 않는다. 신규 엔진은 별도 폴더에서 시작한다.
- 논문 FIGURE(`AGENTS.md` §1~2: 통계 그래프)는 이 기획의 대상이 아니다. 건축 도면에만 적용한다.
- Blender가 원천이므로 Blender MCP 연결 상태와 헤드리스 실행(`blender -b`) 가능 여부는 P0에서 확인한다. 연결이 안 되면 추출은 헤드리스로 한다.
- 3D 대화형 뷰(glb)로 공유하는 방식은 중간발표 작업공간의 방식을 따르되, 이번 기획 범위는 모델 확인용 렌더까지다.
