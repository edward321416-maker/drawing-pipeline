## 0. 왜 새 워크플로우가 필요한가

`docs/specs/2026-11-01-drawing-errorfree-generation-design.md`는 이미 단일 모델 원천, G/T/R/C/P 검사, 결함 장부, 단계 승인을 규정한다. 그러나 현재 `src/architectural_plan_renderer.py` 한 파일에서 프로그램 분류, 가구 배치, 코어 심볼, 조경, 선 위계, 시트 합성을 함께 처리한다. 그 결과, 한 수정이 의도하지 않은 항목을 변화시켜도 기존 QA의 일부 검사를 통과할 수 있다.

기존 보고서의 1층 19/19, 3층 34/34는 **당시 정의된 검사에 대한 통과 기록**이며 제도 완성도와 법규 적합성의 인증이 아니다. 현재 `main`과 `sheets/` 출력물을 **비교 기준(baseline)**으로만 간주하며, 연구자 최종 승인본이라고 표현하지 않는다.

### 변경하지 않을 원칙

1. 3D 모델/태그/설계 데이터가 형상의 원천이다. 도면 렌더러에서 구조·벽·문을 임의 생성·삭제해 원천과 달라지게 하지 않는다.
2. `AGENTS.md` 및 `rules/AGENTS.md`의 승인·출력 구분을 지킨다. 현재 규칙 간 축척·계단형식의 충돌은 조용히 선택하지 않고 결정 장부에 격리한다.
3. 모형·가구·조경·그래픽 표현을 **확인된 모델 형상**, **규칙 기반 설계 제안**, **순수 표현**의 3종 provenance로 태그한다. 표현물이 확정 설계로 둔갑하지 않는다.
4. 작업은 별도 브랜치/PR에서 수행하며 승인 전 `main` 병합, 원본 덮어쓰기, 최종 결과물 폴더로 이동을 금지한다.

## 1. 작업 상태와 통과 조건

각 후보 도면은 다음 상태 중 하나를 가진다.

| 상태 | 의미 | 다음으로 가는 조건 |
|---|---|---|
| `DRAFT` | 설계/표현 가설을 시험 중 | 단계별 자동 검사 |
| `MODEL_VALID` | 원천 모델·기하·계층·프로그램 검사 통과 | 상세 모델 및 연결 확인 |
| `TECH_QA_PASS` | 정축척·선·PDF/DXF·기하 QA 통과 | 사람이 시각·공간 판독 |
| `VISUAL_APPROVED` | 계획 의도와 목표 그래픽 수준에 대해 사용자 승인 | 비교표·재현 증거 첨부 |
| `FROZEN` | **1층 전체**의 계획·모델·가구·제도 품질을 연구자가 최종 승인한 상태. 이후 변경은 새 후보로 분기 | 기술·시각 검증 완료 + 사용자 명시적 최종 승인 |

자동 테스트만으로 `VISUAL_APPROVED` 또는 `FROZEN`을 선언하지 않는다. 검사 실패 후보는 `_rejected`에 보존하고, 합격 후보도 사용자 승인 전에는 최종본으로 부르지 않는다. **G0의 기존 도면 보존은 비교용 데이터 스냅샷일 뿐, 설계 승인·품질 승인·FREEZE가 아니다. 1층은 모든 주요 결함이 해결되고 사용자가 원하는 수준이라고 명시적으로 승인할 때까지 후보를 반복 개선한다.**

## 2. 기본 순서 — 설계 확정과 제도 확정의 분리

### G0 — 비교 스냅샷 확보 및 문제 목록 작성 (먼저 실시)

**입력:** 현재 1층 PNG/SVG/PDF 및 3층 4개 타일, `_check.json`, `qa_report.json`, 사진 참고도면, 규칙·사양서, 사용 중인 .blend/GLB.

**작업:**
- Git HEAD SHA, 모델 파일 hash, 입력 JSON hash, renderer version, Python/Blender 버전, 렌더 seed와 종이·축척을 `manifest.json`에 기록한다.
- 1층 전체와 5개 판독 구간을 고정한다: (a) 시장 중심, (b) 커튼월/주출입구, (c) 코어+화장실, (d) 캡슐, (e) 공원/필로티. 확대 PNG는 동일한 월드 경계·크기·DPI로 비교한다.
- 현행 실패와 위험을 분리해 등록: 11개 기둥 컬링, 4갈래 vs U자형 계단, 3층 벽·문 부재, 출력 엔진 불일치, 타일 인쇄 여백, 가구 수 지표 오해, 하드코딩 대지 좌표.
- 목표 참고 도면에서 **복제할 요소(단면/비단면/가구/해치/조경 위계)**와 **복제하지 않을 요소(실제 대상지·프로그램·치수)**를 분리한다.

**통과:** 같은 입력·seed로 같은 벡터 객체와 동일 이미지가 재현되거나, 재현 불가 사유를 manifest에 명시한다. 기준본이 없다면 비교 시험을 시작하지 않는다.

### G1 — 프로그램 기획 (가구 없이, 평면 프로그램만)

**입력:** 마스터의 실제 구획·출입구·튜브·코어·슬래브, 현행 시장/필로티/서비스/캡슐 등 프로그램.

**작업:**
- 실별 `purpose / primary_activity / users / adjacency / ingress_egress / required_clearance / fixed_objects / evidence_status`를 정의한다.
- 1층 시장 홀을 진입·안내, 판매, 시식/체류, 유동형 행사 영역 등으로 세분하되, 면적 비율은 **설계 가설**로 두고 실제 폴리곤으로 산정한다.
- 주출입구 → 시장 → 수직동선, 서측 공원 → 필로티 → 시장, 서비스 하역 → 운영 구역 경로를 보행 그래프로 구성한다. 서비스 동선과 방문객 주동선 충돌을 확인한다.
- 각 존은 `공용/판매/체류/서비스/전시/피난`의 기능적 역할과 공간 개방도를 갖는다. 입구에서 보이는 시야와 의도적 여백을 정의한다.
- 가구 배치 이전에 주요 동선·문·피난·설비 keep-out을 먼저 예약한다. 통로 폭은 임의 법규 확정치가 아니라 설계 목표/법규 확인 필요 항목으로 분리한다.

**산출:** 모델 유래 구획 오버레이(작업 검토용), 프로그램 매트릭스, 동선 그래프, 면적표(폴리곤 계산), 의도된 비워둔 공간 목록.

**통과:** 모든 존의 목적·접근·관계가 정의되고, 피난 경로가 모델 형상에 의해 차단되지 않음. 중요한 프로그램 재편만 사용자 승인; 세부 가구는 다음 단계에서 자동 진행.

### G2 — 구조·수직교통·실 경계 확정

**작업:**
- 마스터와 슬라이스의 기둥을 ID 기준으로 전수 대조한다. 렌더러의 `core_exclusion.buffer(1.8)`로 기둥을 숨겨 통과시키지 않는다. 중복/매입/실제 충돌을 **원천 모델에서** 해결하고 근거를 기록한다.
- `engine/symbols/stair_core.py`의 4갈래 형상과 `src/architectural_plan_renderer.py`의 U자형 표현 불일치를 해결한다. 하나의 기하 객체에서 평면 그래픽을 파생하도록 한다. 선택 형식의 법규·층고/계단참 적합성은 별도 검증(확인 필요).
- 코어, 화장실, 튜브, 벽, 문은 태그된 3D 모델에 반영한다. 상층 GLB는 프로그램 매스 소스일 뿐 벽·문의 증거가 아니다. 상층의 반복 요소는 1층 기준의 재사용 가능성을 검증한 뒤 층별 변형·개구부를 적용한다.
- 동일 cut geometry가 최소한 모델/단면/도면 사이의 ID·갯수·범위를 유지하는지 비교한다.

**산출:** 승인 가능한 구조·실경계 모델, 구조 일치 보고서, 계단·문·코어 단독 검증 이미지.

**통과:** 실제 모델 객체의 임의 생략 0; 비허용 구조/동선/문 충돌 0; 계단 검토 상태 명시. 모델 확정 후 그래픽 수정이 구조물을 바꾸지 못하도록 잠근다.

### G3 — 프로그램별 가구/인필 설계

**원칙:** 빈 공간 최대 채움이 아니라 공간 사용 방식 표현이다.

- 기능별 가구 카탈로그를 설계한다(시장 진열 매대·벽면 진열·결제/안내·시식, 카페 2/4/8인, 필로티 벤치, 캡슐 전시/휴게, 서비스 하역 설비).
- 가구마다 `family / geometry_source / physical_footprint / visual_footprint / clearance_envelope / orientation / eligible_zone / type_variant`를 갖는다.
- 배치 목적함수는 ① 피난·통과·장애물 제약 충족 ② 주동선과 시야 보전 ③ 활동 영역 간 연결 ④ 적절한 밀도·군집 ⑤ 가구 수의 순으로 둔다.
- 가구 **실물 개수**와 Shapely/SVG **body polygon 개수**를 구분해 계산한다. `furniture_items=140`을 매대 140개로 보고하지 않는다.
- 동일 입력/seed에 대해 2~3개 공간 구성 후보만 내고, 계획적으로 다른 선택지를 비교한다. 단순 무작위 증가/자동 최고 개수 최적화는 지양한다.
- 모델 객체로 확정하지 않은 가구·조경은 `PROPOSED` 또는 `ILLUSTRATIVE` 표기와 출처를 유지한다.

**통과:** 모든 주요 프로그램이 가구만으로 판독 가능; 보행과 장애물 통과; 프로그램별 필수 가구 유형 존재; 설명과 실물 가구 개수 일치. 전체 도면 대신 프로그램별 확대 시트 먼저 검토.

### G4 — 그래픽 스타일 단독 튜닝

**작업:**
- 절단/비절단/유리/가구/기준선/식재의 종이 기준 mm 선종을 **단일 스타일 토큰**에서 생성한다. 현행 T1~T6 숫자를 바로 전면 수정하지 않는다.
- 1:500 대지 전체와 1:100 또는 1:200 확대 검토에서 **종이상 가독성**을 각각 확인한다. 종이 축척에 따라 세부도 수준을 자동 조절한다. 기존 A3 축척 잠금은 유지한다.
- 콘크리트 포셰/유리 이중선/흰 가구 마스크/바닥 격자/외부 점묘/수목의 명암 위계를 고정한다. 선·가구·문 호의 겹침은 순서/마스킹·기하 검사로 제거한다.
- 1개의 고정된 **스타일 시험판**(코어, 유리, 가구, 수목, 경계)에서만 선종 조정 후 300/600dpi 출력 크기로 판독한다. 1:500에서 사라지는 디테일은 무조건 진하게 하지 않고 생략/단순화한다.
- 참고 이미지는 스타일 목표이지 도면에 없는 구조/가구를 생성하는 근거가 아니다.

**통과:** 같은 시험판의 이전/이후를 나란히 비교하고 목표 항목이 개선되며 다른 항목의 명확한 후퇴가 없음.

### G5 — 단일 장면 그래프에서 모든 도면 출력

**목표 인터페이스(미구현, 설계 제안):**

`TaggedModel / ProgramSpec → GeometryPlan → DrawingScene → SVG / PDF / PNG / DXF`

`DrawingScene`은 source_id, floor_id, world geometry(m), role, style_token, z_order, provenance, feature_id, 검증 경계 정보를 갖는다. **동일한 기하 객체가 각 파일 포맷에서 다른 형상/표현으로 다시 계산되지 않는다.**

- `src/02_topology_to_cad.py`와 `src/architectural_plan_renderer.py`가 따로 도면을 그리는 상태를 점진적으로 해소한다.
- `src/04_hybrid_compositor.py`의 A1 출력을 현행 A3 도면과 혼동하지 않는다. 현행 A3 출력 체계를 기준으로 이관하되 A1 파이프라인은 검증 완료 전 유지한다.
- 1:100 2×2 타일의 인쇄 가능 영역, 맞춤 마커, 중첩 영역, 범례 및 축척 막대 위치를 PDF에서 검사한다. 현재 상하 총 높이 592mm와 2장의 A3 총높이 594mm만으로 인쇄 적합을 선언하지 않는다.
- 1층 1:500 전체 도면은 배치·공공 프로그램의 관계를, 별도의 선택형 1층 상세 시트는 참고 도면 수준의 세부를 보여줄 수 있다. 기존 고정 축척 변경 없이 **별도 도면 추가 여부는 사용자 결정**으로 남긴다.

**통과:** SVG/PDF/PNG/DXF 간 도형 수·레이어·위치 및 인쇄 치수가 일치하며 허용 차이는 manifest에 기록.

### G6 — 독립 검사 및 회귀 QA

검사기와 렌더러는 같은 모델 데이터는 읽되 렌더러가 보고한 `collision=0` 자체를 무조건 신뢰하지 않는다.

| 계층 | 검사 | 실패 시 처리 |
|---|---|---|
| 원천 모델 | 태그 누락, source_id 중복, 원천과 단면의 기둥/벽/문 동일성, 층별 개구부 | 모델 단계 반려 |
| 공간/프로그램 | 존 합집합·겹침, 동선 연결, 예약 통로, 운영 동선 분리, 가구 유형/개수 | 계획 단계 반려 |
| 건축 상세 | 계단 높이·계단참, 문 개구/유효통과, 구조 중첩, 화장실 진입 | 상세 단계 반려; 법규 불확실성 별도 표기 |
| 출력 스타일 | 종이 mm·선종, 가구 몸체의 모든 fill, 불필요한 선 중첩, 타일 인쇄 여백, 색상 대비 | 제도 단계 반려 |
| 포맷 일치 | PDF/SVG/DXF 엔티티 대응, scale bar와 세계좌표 비율, 소스와 각 포맷 객체 ID | 내보내기 반려 |
| 사람 판독 | 첫눈 프로그램 인식, 중심/위계, 참고 도면 근접도, 조잡한 부분, 출판 인쇄 가독성 | 시각 재설계 |

- `tests/verify_pipeline.py`의 현재 e2는 `#FFFFFF` 이외의 HEX를 일부 허용하므로, 불투명 가구 몸체 검사는 모든 body 개체의 실제 채움과 불투명도를 독립 확인하도록 강화한다.
- `engine/ledger/ledger.yaml`의 D-001~D-015를 기존 장부로 보존한다. 신규 결함은 D-016부터 추가하고 `원인 단계 / 영향 범위 / 재현 조건 / 실패하는 회귀 테스트 / 수정 커밋 / 상태`를 저장한다.
- 테스트에 고의적인 충돌·누락·잘못된 채움을 주었을 때 실패하는 **부정 테스트**를 반드시 포함한다.
- 이미지 자동 점수만으로 미적 품질 향상을 보증하지 않는다.

### G7 — 전후 비교, 사용자 승인, 동결

한 PR에는 **한 종류의 변경**만 넣는다: 설계/공간, 모델, 가구, 스타일, 출력, 검사 중 하나. 불가피하게 동반 변경이 있으면 별도 이유와 영향 범위를 적는다.

PR 필수 항목:
1. 기준 HEAD와 입력·출력 hash, floor/scale/seed.
2. 이번 변경의 한 가지 가설과 영향을 받아야 할 영역.
3. 변경 파일, 달라진 공간/형상 수, 샘플/전체 테스트 증거.
4. 고정 뷰 기준 **Before/After 동일 영역** 비교.
5. 개선된 항목, 악화된 항목, 미해결 항목과 결함 장부 ID.
6. 결정: `ACCEPT`(개선 입증), `REJECT`(퇴보), `REWORK`(증거 부족).

**중단 규칙:** 같은 원인을 두 번 조정했는데 유의미한 개선이 없으면 숫자 미세 조정을 중지하고 원인 단계(G1~G5)를 재진단한다. 명백한 회귀가 있으면 후보만 폐기하고 이전 기준본을 보존한다.

## 3. 제도 품질 루브릭(사람이 비교, 0~5점)

각 항목은 **기준본 vs 후보 vs 참고 이미지**를 나란히 보면서 판독한다. 이 점수는 주관 평가이며 자동 검사로 위장하지 않는다.

| 항목 | 관찰 기준 | 수용 원칙 |
|---|---|---|
| 공간 읽힘 | 프로그램마다 활동과 공간 관계가 파악되는가 | 목표 존에서 개선 |
| 동선 명료성 | 진입/순환/체류/서비스 분리가 보이는가 | 악화 없음 |
| 가구 타당성 | 유형, 배치, 밀도, 사용 공간의 개연성 | 목표 존에서 개선 |
| 선 위계 | 절단, 투영, 가구, 유리, 배경의 차이 | 악화 없음 |
| 해치·조경·톤 | 표기 이유가 있고 배경이 건축을 압도하지 않는가 | 악화 없음 |
| 세부 정리 | 선 겹침, 문·글자·기구 충돌 및 인쇄 가독성 | 기존 결함 재발 0 |

원칙적으로 새 후보는 **타깃 항목을 개선하고, 기존에 합격한 핵심 항목을 후퇴시키지 않아야** 채택한다. 단순 총점 상승으로 안전/구조 결함을 상쇄할 수 없다. 한 번에 모든 항목을 고치려 하지 않는다.

## 4. 시간·비용 최적화

- **렌더링 3단계:** (i) 모델·벡터만 빠른 시험 → (ii) 5개 고정 크롭 렌더 → (iii) 후보 수용 시에만 전체 A3 PDF/PNG, DXF, 3D 필요 시 Modal.
- **해시 캐시:** 모델 hash가 같고 스타일만 바뀌면 Blender 재절단 금지. 프로그램만 바뀌면 모델 고정 부분의 캐시 활용. 타일만 바뀌면 전체 모델 계산 재수행 금지.
- **재현성:** 후보별 seed, 파라미터, 축척, 소스 SHA와 출력을 manifest로 기록. 비결정적 AI 인필은 후순위에 둔다.
- **분업:** 공간 계획자(프로그램 의도) → 기하 모델러(물리 정합성) → 도면 엔진(표현) → 독립 QA(반례) → 사용자(핵심 설계/시각 승인). 한 사람이 여러 역할을 수행해도 검사는 별도 스크립트/리뷰로 독립성을 확보한다.
