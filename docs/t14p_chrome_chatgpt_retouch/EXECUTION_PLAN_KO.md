## 0. 사용자 요구와 판정
요구는 **Blender 렌더를 Chrome의 ChatGPT 웹 UI에 실제 첨부하고, ChatGPT Images 편집 결과 PNG를 다운로드하여 건물 자체의 재질·빛·건축 사진 같은 표현을 개선하는 것**이다. "Blender만 렌더", "배경만 AI", "원본 건물 JPG에 색보정"은 미충족.

PR #25에는 119,486 vertices / 237,093 triangles / 391 objects의 소스 메시에서 나온 Cycles A/B 4800×2700가 있다. 보고서와 커밋 파일 목록에 ChatGPT 웹 업로드, 편집 내역, ChatGPT 결과 PNG, 브라우저 다운로드 수령 기록은 없다. 따라서 GPT 리터치 수행 증빙은 **0건**이며 `CHATGPT_BROWSER_EDIT_NOT_PERFORMED` 로 기록한다. Blender 원본은 `BLENDER_PBR_SOURCE`이며 최종 공모전 리터치로 표시하면 안 된다.

실제 GitHub PNG 프리뷰를 시각 확인한 결과: Daylight는 반사/재질이 단순하고, 주변 건물은 회색 블록, 수목은 구체형, 인물/거리 생활감 부족. Blue Hour는 전반이 지나치게 어두워 건축 입면/보이드/정원/튜브가 읽히지 않는다.

**참고 이미지** (각각 확인된 자료만): A/B Blender 원본, 정면·지붕·중층 보이드·저층부 크롭, 원본 모델 실루엣/층수/튜브 T1–T4 보호 마스크, 필요 시 신뢰할 수 있는 재료 참고. 구조 오버레이는 **참고용**이며 생성 이미지에 합성하지 않는다. 한 메시지에 너무 많은 이미지가 들어가면 메인/구조 참조를 우선한다.

## 2. Chrome → ChatGPT 실제 작업
1. **이미 로그인된 사용자의 Chrome**에서 `https://chatgpt.com/`을 열고 새 대화를 시작한다. 새 계정 생성, 별도 API/OAuth/과금, 쿠키/토큰 추출, Chrome 프로필 복제, 브라우저 디버그 포트 강제 접근 금지.
2. ChatGPT의 **+ → 사진 및 파일 추가** 또는 이미지 드래그앤드롭으로 `G002_A_*_UPLOAD_ONLY.jpg` 및 보호/참고 이미지 첨부. 썸네일 및 실제 파일 선택 확인. 이미지를 첨부하지 않은 프롬프트 단독 실행은 불인정.
3. 별도 프롬프트 파일 `G002_CHATGPT_EDIT_PROMPTS_KO.md`의 Daylight 요청을 붙여 넣고 **기존 이미지를 편집한 새로운 PNG 이미지를 생성**하라고 요구한다. 텍스트 설명만 나오면 편집 미실행으로 기록.
4. 실제 생성 이미지를 열어 **Save/다운로드**하고 파일 자체가 존재하는지 확인. 브라우저 다운받은 파일 형식·치수·크기·해시 검증. `G002_A_GPT_PASS01_RAW.png` 등으로 보존(원본 덮어쓰기 금지).
5. Blue Hour는 새 대화/분리된 입력과 B 전용 프롬프트로 처리. A 출력의 색만 어둡게 변환해서 B라고 표시하지 않는다.
6. 1차 생성물이 원본의 층판, 코어, 튜브, 보이드, 수평 입면 띠, 지붕 원형 개구부를 바꾸었으면 **건물 전체를 버리거나 Blender 건물을 통째로 덮어씌우지 않는다**. 이미지 편집 영역 선택을 통해 바뀐 부분만 재지시하거나, 보호된 재질/입면 영역만 별도 패스로 수정을 요청한다. 선택 범위가 정확하다고 가정하지 않는다. 같은 오류가 지속되면 `REJECTED_GEOMETRY_DRIFT`로 보류하고 해당 부분을 원본 모델 기반 3D 재렌더 및 전문 편집으로 해결한다.
7. **3가지 표적 편집 패스**를 순서대로 시도: (i) 주변 건물·실제 나무·지면·보행자/거리, (ii) 건물 표면의 물성·유리 반사·접지 그림자, (iii) 톤 통일·촬영 느낌·대기 깊이. 단순 색보정만 남은 결과는 실패.
8. 각 패스 후 다시 PNG 저장, 해시 기록 및 100% 확대 원본 비교. 화질·형상 보존 둘 다 통과한 후보만 최종 합성.

**자동화 현실성 경계**: Codex가 현 컴퓨터에서 *권한이 부여된 실제 브라우저 GUI 조작*을 제공할 경우 실제 사용자 인터랙션으로 진행. 그렇지 않으면 브라우저 조작을 **실행한 척하지 말고** 입력 패킷/프롬프트/수령 폴더를 준비하고 사용자가 Chrome에서 파일을 첨부하고 저장하는 최소 수동 단계만 명시한다. 인증을 우회하는 Playwright/Chrome cookies 접근 금지. 이 계획 작성 시점 ChatGPT 쪽 세션에는 Chrome 제어 도구가 없으므로 브라우저 편집 실행 **미확인**.

공식 참고: https://help.openai.com/en/articles/11084440-images-in-chatgpt · https://help.openai.com/en/articles/8400551-chatgpt-image-inputs-faq

## 3. 시각화 결과 기준: '실제 건물 같은 사진'
**A Daylight**: 뒤의 건물들은 형태를 유지하되 회색 모델링 블록처럼 보이지 않는 자연스러운 재질/창호/원근 처리; 녹색 구체 나무를 실제 수목 질감으로 교체; 근경 포장/도로/사람 스케일; 3D 건물 실제 판·띠·코어·개구부 유지하면서 유리의 반사/투명도, 입면 표면 거칠기와 매끄러운 접지 그림자. HDR/과포화/CG 렌더풍 회피.
**B Blue Hour**: 블루아워 노출을 올려 각 층·중간 정원·지붕·튜브가 읽히도록; 검증된 개구부에만 자연스러운 실내등; 거리와 사람의 실제 생활감, 과장된 네온/모든 창의 균일 조명 금지.
**공통**: 원본 같은 카메라, 똑같은 건축 높이·실루엣·층수·수평 슬래브/띠, A–D 코너 코어, T1–T4 튜브, 중층 보이드, 지붕 원형 개구부 유지. 검증되지 않은 실제 주소·시공재료처럼 표현하지 않음. 원본 이미지는 **설계 근거**, ChatGPT 편집본은 **개념 시각화 제안**.

## 4. 게이트 분리
(A) **전송/생성 사실**: 브라우저 실제 파일 첨부가 확인되고 생성된 PNG가 실제 다운로드되었는가? 첨부 파일 SHA, 메시지/실행 캡처(개인정보 가림), 결과 PNG SHA, 버전·시간을 남긴다. 브라우저 작업을 대체하는 API/파이썬 생성 이미지로 증빙하지 않는다.
(B) **건축 형상 정확성**: source ↔ result 동일 비율·카메라·모서리 대응점을 대조. 100% 확대 타일 6개(지붕/상부 띠/중간 정원/튜브/코어/저층 접지). 기하가 바뀌면 인쇄 승인 금지. 보호선 상관계수만으로 PASS 금지.
(C) **시각화 완성도**: 사람 눈으로 건물 재질·반사·그림자·수목의 자연스러움·도시 맥락·사람 스케일·Blue Hour 노출을 개별 1~5점 평가. 개별 4점 이상 및 독립 검수 필요. 특히 **건물 자체**가 실사형으로 변했는지 필수.
(D) **인쇄**: ChatGPT 생성 이미지의 *실제 픽셀*로 396mm 인쇄 기준 DPI 계산. AI 생성 결과가 낮은 해상도인 경우 원본 4800px의 해상도를 그대로 지녔다고 주장하지 않는다. 확대는 인쇄용 보간에 불과하며 건축 상세의 사실 근거 아님.

상태: `CHROME_HANDOFF_PENDING` → `GPT_IMAGE_DOWNLOADED_UNREVIEWED` → `GEOMETRY_REVIEW_PENDING` / `VISUAL_QUALITY_REVIEW_PENDING` → `APPROVED_FOR_LAYOUT_NOT_DESIGN_APPROVED`. 원본 검수 실패 시 `REJECTED_GEOMETRY_DRIFT`, 실제 브라우저 사용 불가 시 `BROWSER_CONTROL_UNAVAILABLE`.
